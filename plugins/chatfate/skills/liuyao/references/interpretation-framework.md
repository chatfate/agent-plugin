# 六爻解释框架

## 0. 判词先行与三层写法

先完成全盘分析，再给答案；不要边读一条事实边写结论。

- `verdict.judgment`：先解释本问应关注什么，再串起卦意、关键依据与变化条件，通常 120–200 字；可用空行分成两三个短段落。不能为追求短而删掉支持或牵制判断的条件。
- `verdict.timing`：只写 `timingTriggers` 已有窗口条件；无据为 `null`，不写保证。
- `verdict.action`：只给一个动作，限调整节奏、收尾兑现、主动沟通、准备打磨、休整蓄力、择时行动、规避具体风险面。
- `duanyu`：模块方向判断。
- `shiyi`：把断语讲明，说明关键事实之间的支持、牵制和转折。
- `cankao`：把判断落为白名单动作；凡保留模块必须非空。

三层不得复制、近义改写或拆句填充。正文用判断句；置信度放数据字段，具体限制在相关判断旁说明，方法边界集中进入 boundaries。

## 1. 所问主题、subject 与用神候选

- 从 `useGod.targetRelatives` 和 `useGod.groups` 读取引擎映射出的目标六亲、候选爻和选择状态。
- 先说明选取状态，再分析候选。若 `selectionStatus` 为 `ambiguous` 或 `missing`，或同组有多个同等可行候选，不把 `selected` 扩写成无争议的唯一用神。
- 读取 `normalizedInput.subject` 只为解释已发生的确定性映射：自己按 topic，`family` 的新卡片范围是“父母 / 长辈”，引擎以父母爻为用；替朋友问时以兄弟爻为用。`family` 不适用于子女、伴侣或同辈亲属，旧报告也不能据此认定用户问的就是父母。模型不改变 seed，不重起卦，也不替引擎另选用神。
- subject 对用神映射有影响时，`questionFocus.duanyu` 用一句判断交代，但 `evidenceRefs` 仍只引用引擎输出的 `calculatedFacts.useGod`；`normalizedInput.subject` 不进入 evidenceRefs。
- 用户原问题只用于理解语境；报告中的事实判断必须由 `calculatedFacts` 支撑。
- 不将宽泛问题改写成更具体的医疗、投资、诉讼或关系结论。

## 2. 月日、旺衰与旬空

- 以每爻现成的 `strength` 和 `monthDayInfluence` 为准，不根据纳甲地支重新计算旺衰。
- 区分 `strength.state`、`specialStatus` 与月日作用；不要把其中一个标签替代整套状态。
- 旬空只使用 `voidState`、`voidBranches` 和引擎证据。不可仅凭“空”字断定无效、失败或永远不发生。
- 综合用神时，至少同时引用候选爻与其旺衰/月日字段。

## 3. 动爻与变卦

- 从 `movingLinePositions` 和对应 `lines[index].isChanging` 确认动爻。
- 解释动变时结合 `movementState`、`changedLine` 与 `changedHexagram`；缺少变爻或变卦时不要补算。
- 多动爻应分别说明，再指出它们是否支持同一主题。不可只挑最符合预期的一爻。
- 无动爻时只说明结构相对静态，不等同于事情不会变化。

## 4. 世应与关系结构

- 从 `shiLinePosition`、`yingLinePosition` 及六爻的 `isShi`、`isYing` 交叉确认。
- 世应可作为主客、自身与外部条件的传统观察框架，但具体对应谁必须服从问题语境；不可自动等同于固定人物。
- 比较世应时引用双方的六亲、纳甲、五行、旺衰及月日字段。只说结构差异，不推断隐私、动机或道德。
- `hexagramRelations`、伏神与六神只作补充，不覆盖用神和动变主线。

## 5. 补充系统

- 伏神只在 `hiddenSpirit` 或 `hiddenSpirits` 实际存在时讨论。
- 六神、神煞、长生、卦身和派生卦象属于补充证据。单独出现不能升级为 `high` 置信度，也不能决定吉凶。
- 当不同系统给出方向不一致的线索时，保留冲突并降低置信度，不强行统一。

## 6. 经文到所问的解释链

报告渲染器从版本化静态经文表输出本卦与变卦经文；模型只负责解释，不凭记忆补经文。链条固定为：

`卦名 → 经文 → 释经 → 盘面 → 所问`

- `trend.shiyi` 第一条先把本卦经文讲白，再用盘面事实检验该方向。
- 有变卦时可补充变化走向，但本卦为主、变卦为辅。
- 释经、盘面和所问之间必须有明确逻辑连接；经文不得孤悬成装饰。
- 经文原文不进入 evidenceRefs；释经后的盘面判断仍必须引用真实 `calculatedFacts`。

## 7. 时间线索

- 只解释 `timingTriggers` 中现成的目标六亲、地支、触发条件与依据。
- 时间线索描述“传统框架下值得留意的条件”，不承诺某日发生某事。
- 引擎没有时间触发时令 `verdict.timing = null` 并删除 timing 模块，不保留空模块。

## 8. 边界章写法

优先披露会改变解释的具体因素：

- 用神候选未决或同组多候选。
- 多动爻产生不同方向。
- 世应对应关系受问题语境影响。
- 伏神、旬空、神煞或不同补充系统之间存在张力。
- 引擎未返回可用的时间触发。

边界不是通用免责话术；应引用造成限制的实际事实路径。正文允许明确表达不确定性；边界应说明哪些条件会改变判断，不隐去反证。

## 置信度

- `high`：只复述引擎明确给出的卦盘事实。
- `medium`：由用神、旺衰、动变、世应等多个明确事实共同支持的传统解释。
- `low`：存在多个候选、替代解释、流派口径或上下文歧义。

一条文本同时包含事实和解释时，按解释层标记，不得使用 `high`。低置信内容进入 boundaries 或不写，不把正文改成连续的“可能、也许、仅供参考”。
