# 解释框架

## 0. 命局速写与三层写法

- `synopsis`：全盘完成后收敛 3–5 条判断句；每条至少两个独立事实组，写结构底色与当前阶段的可验证方向，不写万金油或人格宿命。
- `duanyu`：先给模块或域的方向判断。
- `shiyi`：解释事实之间如何相互支持、牵制，正反并举。
- `cankao`：给一个清晰的白名单动作或先后顺序。

三层正文职责不同，不复制、近义改写或拆句填充。判断要清楚；不确定性集中进入 boundaries，不把正文写成 hedge 墙。

## 分析层级

### 1. 日主与时间背景

- 从 `dayMaster` 确认日主五行与阴阳。
- 从月柱和 `solarTermContext` 确认工具给出的时间背景。
- 可以说明日主五行与月柱显性五行之间的生克关系，但不能由此单独判定旺衰、格局或喜忌。

### 2. 显性结构与藏干

- 分开观察四柱天干、地支主五行和藏干，不把藏干与透干视为同等显著。
- `elementCounts` 只描述工具采用的计数口径。数量多寡不自动等于得令、得地、得势或强弱。
- 柱间关系必须引用所有参与关系的柱位。若引擎没有输出合化是否成立，不要断言已经合化。

### 3. 十神组合

- 先观察显性天干的十神，再将藏干十神作为补充层。
- 至少用两个位置形成“组合”后再讨论主题；单个十神只能做局部说明。
- 使用“表达方式、关注点、行动倾向、资源组织、规则压力、学习支持”等中性语言，不贴人格、职业、婚姻或财富标签。
- 同一组事实可能支持多种表现方式。优先说明张力和条件，不给固定人格结论。

### 4. 大运

- 只使用 `luckCycles` 已给出的顺序、起止年份、起运年龄与柱。
- 先复述时间边界，再优先展开 `calculatedFacts.currentLuckCycle`：active 时用 `index` 和 `cycle`；not_started 时只谈 `nextCycle`，不得把下一步写成当前。
- 可引用引擎已给的 `calculatedFacts.liunian` 说明当前年干支和日主十神关系；不从当前日历自行补算，也不猜用户现实事件。
- 大运和流年只形成阶段主题，不转换成具体事件，不保证结果。

### 5. 边界章写法

- 综合结论至少引用两个独立事实，指出支持关系和可能的反向关系。
- 正文使用判断句；行动属于参考层，限调整节奏、收尾兑现、主动沟通、准备打磨、休整蓄力、择时行动、规避具体风险面。
- 对引擎未提供的旺衰、格局、喜用神、流月与具体事件保持沉默，或在确实影响理解时写入 boundaries。
- 边界必须具体且有事实依据，不得收回正文已经给出的判断。

## 四域映射

总规则是“贴域不贴命”：固定映射已有事实，给域内方向与行动，不给确定事件、结果保证、人格命定或隐私推断。单星不成题，域内证据薄就如实说薄。

- career：官杀＋印＋食伤。看职责／平台压力、凭据／学习支持、输出能力的组合。
- wealth：财＋食伤＋比劫。看资源组织、来源与分配牵制，不谈具体标的或收益保证。
- love：日支＋财官，中性并观。不按性别推定角色，不推断具体对象、忠诚或隐私。
- health：五行偏枯＋日主受克。只写养护方向与如实就医提示，不病断、不吓人。

每域至少一条断语、两条释义和非空参考。先说得用处，再说短板和解法；参考先给长期赢法，再结合 `currentLuckCycle` 与 `liunian` 的真实事实给当前段提示。

## 总参考职责

- `overallGuidance.duanyu`：恰好一条跨域总断。
- `overallGuidance.shiyi`：恰好一条，解释总断依据和四域先后关系。
- `overallGuidance.cankao`：2–4 条，按优先级收束，每条只写一个判断与动作方向。

不得把四域全文重写到总参考，不得复制同一段或拆句填充三层。

## 基础关系词典

- 木生火、火生土、土生金、金生水、水生木。
- 木克土、土克水、水克火、火克金、金克木。
- 同五行可描述为同类关系，但不能直接等同于助力或竞争。
- 生克只是一层传统关系。没有经过确定性算法给出的旺衰结果时，不能仅凭生克或计数判断身强身弱。

## 十神解释边界

十神只表示传统框架下日主与其他天干之间的关系。解释组合而非孤立标签：

- 比肩、劫财：自主、同辈、竞争或协作主题。
- 食神、伤官：表达、输出、创造与规则张力。
- 正财、偏财：资源组织、交换和现实投入。
- 正官、七杀：约束、责任、压力和秩序。
- 正印、偏印：学习、支持、抽象理解和保护。

不得从单个十神直接推出职业、财富、婚姻、健康或道德品质；四域判断必须按固定映射使用组合证据。

## 置信度

- `high`：仅复述计算器明确给出的字段，不添加传统推断。
- `medium`：由多个明确事实支持、推导过程透明的基础关系解释。
- `low`：存在同样合理的替代解释，或结论明显受门派、口径、缺失事实影响。

一条文本同时包含事实和解释时，按解释层标记，不得使用 `high`。低置信内容进入 boundaries 或不写，不把正文语气降成连续的“可能、也许、仅供参考”。
